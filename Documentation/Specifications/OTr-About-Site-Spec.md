# OTr About Site — Specification

**Date:** 2026-05-19
**Author:** Wayne Stewart / Claude
**Status:** Complete

---

## 1. Purpose

The About site is a static HTML reference website embedded inside the OTr component. It is displayed in a 4D web area form when `OTr ABOUT` is called. The site covers every public API method, explains the OT→OTr naming convention, and serves as the primary developer reference without requiring an external browser or internet access.

---

## 2. Entry Point

Calling the project method `OTr ABOUT` (space-separated, 4D naming convention) opens the form `OTr ABOUT` in a new single-instance process. The form contains one object:

| Object | Type | URL source |
|--------|------|-----------|
| `webAreaDocs` | Web area (embedded engine) | `Form.webAreaURL` |

The method resolves `Form.webAreaURL` from the 4D virtual path `/RESOURCES/about/index.html`, converting it to a `file://` URL. If the file is absent, an alert is shown rather than opening the window.

Window title: **OTr Reference**

## 3. Source Files

All source files live under `Resources/about/`. They are part of the compiled component and are therefore distributed with it.

```
Resources/about/
  build-otr-docs.mjs      Build script (Node.js ESM)
  index.html              Overview page
  commands.html           Full method index grouped by category
  naming.html             OT ↔ OTr name-mapping table
  assets/
    styles.css            Stylesheet (generated by the build script)
  commands/
    otr-new.html          One page per public method (111 files)
    otr-get-text.html
    …
```

The `commands/` directory and `assets/styles.css` are fully generated. Do not edit them by hand — rerun the build script instead.

## 4. Build Process

The build script is a self-contained Node.js ESM module. Run it from `Resources/about/`:

```sh
node build-otr-docs.mjs
```

**What the script does:**

1. Deletes and recreates `commands/` (idempotent).
2. Reads every public API method listed in `methodGroups` from `Documentation/Methods/<MethodName>.md`.
3. Parses each `.md` file to extract signature, description, attributes, and parameter table.
4. Generates individual HTML pages in `commands/`.
5. Generates `commands.html` (grouped index), `naming.html` (OT↔OTr map), and `index.html` (overview).
6. Writes `assets/styles.css`.

**Node.js availability:** There is no system `node` in this environment. Use the binary bundled with the Codex application:

```sh
"/Applications/Codex.app/Contents/Resources/node" build-otr-docs.mjs
```

**When to rebuild:**

- After updating any `Documentation/Methods/OTr_*.md` file.
- After adding or removing public methods from `methodGroups` in the script.
- After modifying the script itself (styles, layout, content).

## 6. OT → OTr Naming

The ObjectTools 5.0 plugin named commands with a space prefix: `OT GetText`, `OT PutLong`. OTr replaces `OT ` with `OTr_`: `OTr_GetText`, `OTr_PutLong`.

The build script encodes two exception sets:

**`noOtEquivalent`** — methods that have no ObjectTools 5.0 counterpart. These show an "OTr only" badge on the naming page and `"No ObjectTools 5.0 equivalent"` on their method page. Current members:

> `OTr_LoadFromText`, `OTr_LoadFromGZIP`, `OTr_SaveToGZIP`, `OTr_LoadFromXMLFile`, `OTr_SaveToXMLFile`, `OTr_SaveToXMLSAX`, `OTr_SaveToXMLFileSAX`, `OTr_ImportLegacyBlob`, `OTr_GetActiveHandleCount`, `OTr_GetHandleList`, `OTr_IncludeShadowKey`, `OTr_Register`, `OTr_LoadAndViewOTBlob`, `OTr_ObjectViewer`, `OTr_CompiledApplication`, `OTr_GetVersion`, `OTr_onStartup`, `OTr_onExit`

**`changedBehaviour`** — methods that exist in both but produce incompatible output. These show a "Changed behaviour" badge and a top-of-page amber warning banner:

> `OTr_SaveToText`, `OTr_LoadFromBlob`, `OTr_SaveToBlob`, `OTr_BLOBToObject`, `OTr_ObjectToBLOB`, `OTr_ObjectToNewBLOB`

## 7. Documentation Source Format

Individual method documentation is drawn from `Documentation/Methods/<MethodName>.md`. The parser (in `readDoc()`) expects:

```
<!--[raw metadata comment — ignored by parser]-->
## OTr_MethodName
Signature line
Description paragraphs…

**OPTIONAL SECTION HEADING**
Further paragraphs…

Attributes: Shared, Invisible, Preemptive indifferent
| Parameter | Type |  | Description |
| --- | --- | --- | --- |
| param | type | ➡️ | description |
| Result | type | ⬅️ | description |
```

The parser strips the HTML comment, identifies the title, signature, attributes, description, and parameter table. The description renderer handles inline markdown (`*em*`, `**strong**`, `` `code` ``) and converts section headings (`**WARNING: ...**`, `**NOTE:**`, `**ORIGINAL DOCUMENTATION**`) to styled notice boxes:

| Heading pattern | Rendered as |
|----------------|-------------|
| `**WARNING: ...**` | Amber notice box |
| `**NOTE:**` | Blue notice box |
| `**ORIGINAL DOCUMENTATION**` | Subdued grey aside |

## 8. Visual Design

- **Accent colour:** deep blue `#1a4fbd` / `#12388a` (distinguishes from the Logging component's green)
- **Background:** `#f4f6fb`
- **Code syntax colours:** commands in `#0060a8` (blue-bold), keywords in `#005a00` (dark green), locals in `#1d3fba` (indigo), constants in `#6500a0` (purple)
- **Responsive:** two-column layout collapses to single column below 780 px
- **Typography:** system sans-serif; monospaced code with `Courier Prime` preferred

The CSS is entirely generated by `writeStyles()` in the build script — it is not a separate maintained file.

## 9. Adding or Changing Methods

### To add a new public method

1. Ensure `Documentation/Methods/OTr_NewMethod.md` exists with the standard format (§7).
2. Add `"OTr_NewMethod"` to the appropriate group's `methods` array in `build-otr-docs.mjs`.
3. If the method has no OT equivalent, add it to `noOtEquivalent`.
4. If its serialisation output differs from the plugin, add it to `changedBehaviour`.
5. Rebuild: `node build-otr-docs.mjs`.

### To remove a method

Remove it from its group's `methods` array and rebuild. The script automatically deletes and recreates the `commands/` directory, so the stale page will disappear.

### To modify layout or styles

Edit `build-otr-docs.mjs` (the `layout()`, `writeStyles()`, or page-generator functions) and rebuild.

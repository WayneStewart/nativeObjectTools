What is OTr?

OTr stores typed 4D values—scalars, arrays, nested objects, pictures, BLOBs, records—in native 4D Objects indexed by dotted string tag paths. Objects are referenced by integer handles, exactly as in the original ObjectTools plugin.

Because OTr is a compiled 4D component rather than a binary plugin, it works identically on Apple Silicon and Intel Macs, on Windows, and under all 4D execution modes including compiled and preemptive-capable processes.

The public method names use the OTr_ prefix. For drop-in compatibility with existing code that calls OT xxx, the host project can install thin wrapper methods that forward to the component.

// Create a new object and store some values
var $h_i : Integer
$h_i := OTr_New

OTr_PutLong($h_i; "customerID"; 1042)
OTr_PutText($h_i; "name"; "Acme Corp")
OTr_PutBoolean($h_i; "active"; True)

// Read values back by tag path
var $name_t : Text
$name_t := OTr_GetText($h_i; "name")  // → "Acme Corp"

// Nested paths work with dot notation
OTr_PutLong($h_i; "address.postcode"; 2000)

// Serialise to JSON
var $json_t : Text
$json_t := OTr_SaveToText($h_i; True)

// Release when done
OTr_Clear($h_i)

OT vs OTr

ObjectTools plugin methods were named with a space: OT GetText, OT PutLong. The OTr equivalent replaces OT  with OTr_: OTr_GetText, OTr_PutLong.

For the handful of OTr methods that have no ObjectTools equivalent—such as OTr_LoadFromText and OTr_GetVersion—the naming convention still applies but there is no legacy call to migrate from.

A small number of serialisation methods produce output that is not compatible with the plugin's own format. Those methods carry a warning in their reference page.

Full OT → OTr name map 
// ObjectTools 5.0 plugin
OT PutLong ($handle; "id"; 1042)
$name := OT GetText ($handle; "name")

// OTr component — same semantics, new name
OTr_PutLong($handle_i; "id"; 1042)
$name_t := OTr_GetText($handle_i; "name")
